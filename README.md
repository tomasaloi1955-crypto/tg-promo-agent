# tg-promo-agent

Промо-агент в облаке (GitHub Actions) — не зависит от того, включён ли ваш компьютер.
Раз в день ищет один публичный Telegram-чат под тему дня и публикует туда рекламный
пост одного из ваших каналов. Темы крутятся по кругу:

| Тема дня | Канал | Ссылка |
|---|---|---|
| спорт | Мусульманка на спорте | t.me/ilikeislamandsport |
| образование | Тамра | t.me/tamra_school |
| ИИ / автоматизация | Halal AI \| Freya | t.me/Halalaifreya |
| семья / ислам | Тамра | t.me/tamra_school |
| арабский язык | My Arabic | t.me/myarabicl |
| английский язык | I Speak English | t.me/i_speak_en |

Тексты постов — `promo_posts.json`, баннеры — `banners/*.png` (`make_banners.py`
их генерирует, Pillow).

## Как это работает

1. GitHub Actions запускает `promo.py` раз в день по расписанию (`.github/workflows/promo.yml`,
   время — cron в UTC, поправьте в файле под свой часовой пояс) — либо вручную кнопкой
   **Run workflow** на вкладке **Actions** в GitHub.
2. Агент ищет чат по ключевым словам темы дня (Telegram, глобальный поиск), отсеивает
   каналы (туда обычный участник не пишет), малолюдные и уже использованные чаты.
3. Вступает в подходящий чат, читает описание/закреп, спрашивает Gemini, разрешён ли
   там самопиар.
4. **Публикует пост СРАЗУ — без подтверждения человеком — но только если Gemini дал
   чёткий вердикт «allowed»** (не «conditional»/«unclear»: без человека, который бы
   перепроверил, эти случаи слишком рискованны, поэтому агент их просто пропускает и
   ищет следующий чат).
5. Присылает вам в Telegram сообщение с итогом — что опубликовано и куда, или почему
   сегодня публикации не было.

**Важно:** в локальной версии (`tg-channel-agent` на компьютере) каждый пост ждал
вашего подтверждения кнопкой. Здесь это сознательно убрано — GitHub Actions запускает
процесс разово по расписанию и не может слушать нажатия кнопок в Telegram. Это ваш
выбор при переносе в облако: полная автоматизация ценой более высокого риска бана/
спам-репорта, если Gemini где-то ошибётся в оценке правил чата.

`promo_sport.py` + `.github/workflows/promo_sport.yml` — отдельное звено, добавлено

ротации спорт получал долю раз в 6 дней вместе с остальными 5 каналами). Работает
пн-пт (07:30 UTC), использует ту же логику поиска/публикации, что и `promo.py`, но

(`promo.py`/`promo.yml`) эта доп. рассылка не меняет.

## Поиск клиентов на автопостинг (outreach.py)

`outreach.py` + `.github/workflows/outreach.yml` — ищет клиентов для услуги «канал ведётся
сам» (сама услуга — `clients.py` в репозитории `pilatesbot`). Раз в день (09:00 UTC):

1. Глобальным поиском Telegram ищет **каналы** целевой аудитории: магазины и бренды,
   эксперты/тренеры/преподаватели, онлайн-школы, мусульманские проекты
   (слова — `SEARCH_KEYWORDS` в `outreach.py`).
2. Оставляет те, где: 300–30 000 подписчиков, в описании есть @контакт владельца (живой
   человек, не бот и не канал), канал живой (пост за последние 45 дней), но постит редко
   (≤ 20 постов за 30 дней — владельцу не хватает времени). Запрещённые ниши (ставки,
   алкоголь, табак, кредиты, 18+, «заработок» и т.п.) отсекаются.
3. Gemini ещё раз проверяет, подходит ли канал, и пишет **личное первое сообщение**
   владельцу: с деталью из его канала, предложением 3 бесплатных пробных постов и ссылкой
   на ваш пост с услугой.
4. Присылает вам в Telegram до 5 клиентов в день: канал, ниша, активность, ссылка
   «Написать» и следующим сообщением — готовый текст. Вы копируете и отправляете сами.

Каждый канал проверяется один раз, каждому контакту пишем не больше одного раза —
всё в `outreach_memory.json` (workflow коммитит его сам). Репозиторий публичный, поэтому
там хранятся не @username-ы, а их зашифрованные отпечатки (ключ — секрет `API_HASH`), а в
журнал Actions не пишутся ни каналы, ни контакты, ни тексты: всё это приходит только вам
в Telegram.

**Защита аккаунта от ограничений за спам** (24.09.2026 аккаунт уже ограничивали на сутки
по жалобе):
- первое письмо короткое, **без ссылок, @упоминаний и цен**, заканчивается вопросом
  («Можно расскажу подробнее?»). Ссылку и цены агент присылает отдельным «вторым
  сообщением», его отправляют только тем, кто ответил;
- первым берётся контакт «по рекламе/сотрудничеству», в карточке отмечено, если у канала
  открыты комментарии: туда писать безопаснее, чем в личку;
- не больше 5 клиентов в день, в отчёте есть напоминание писать с перерывами 10–20 минут;
- перед каждым прогоном агент спрашивает @SpamBot. Если аккаунт ограничен, присылает
  предупреждение с датой снятия и ничего не отправляет сам.

**Свой список каналов.** Actions → «Поиск клиентов на автопостинг» → Run workflow → в поле
«Каналы» впишите до 10 каналов (`@name` или ссылки `t.me/name` через пробел). Агент не ищет
сам, а пишет письмо под каждый из этих каналов и присылает вам в Telegram. Фильтры частоты
постов и числа подписчиков тут не действуют, отсекаются только запрещённые ниши. Если у
владельца закрыты сообщения от незнакомых или контакта нет, агент всё равно даст текст
и подскажет, куда его отправить. По приватным ссылкам-приглашениям (`t.me/+…`) агент вступает в канал (пауза 20–45 с после каждого вступления), а если вступление по заявке — подаёт заявку и сообщает об этом.

**Автоотправка выключена сознательно.** Сообщения незнакомым людям с личного аккаунта —
главная причина спам-блока, а этот же аккаунт ведёт промо-агента. Если всё же нужно:
Settings → Secrets and variables → Actions → **Variables** → `OUTREACH_AUTO_SEND` = `1`.
Тогда агент сам пишет не больше 3 владельцам за прогон (потолок 5, паузы 1,5–4 минуты)
и останавливается при первом предупреждении Telegram о спаме (PeerFlood).

Ссылка на пост с предложением — переменная `OUTREACH_OFFER_LINK`
(по умолчанию `https://t.me/Halalaifreya`; лучше указать ссылку на сам пост,
например `https://t.me/Halalaifreya/123`). Секреты — те же, что у промо-агента.

## Настройка (один раз)

### 1. Секреты репозитория (Settings → Secrets and variables → Actions)

| Секрет | Что это |
|---|---|
| `API_ID`, `API_HASH` | с https://my.telegram.org → API development tools (те же, что в tg-channel-agent) |
| `TELETHON_SESSION` | строка-сессия аккаунта — получить `get_session_string.py` (см. ниже) |
| `GEMINI_API_KEY` | https://aistudio.google.com/apikey |
| `BOT_TOKEN` | токен бота-уведомителя у @BotFather (можно тот же, что у бота-пульта tg-channel-agent) |
| `OWNER_ID` | ваш числовой Telegram id (@userinfobot) — куда слать уведомления |

### 2. Получить `TELETHON_SESSION`

На компьютере, где уже авторизован `tg-channel-agent` (файл `userbot.session` существует):

```powershell
cd путь\к\tg-promo-agent
copy ..\tg-channel-agent\userbot.session .
venv\Scripts\python get_session_string.py
```

Выведет длинную строку — это и есть `TELETHON_SESSION` (храните только в GitHub Secrets,
никуда больше — она равносильна паролю от аккаунта). Файл `userbot.session` после этого
можно удалить из папки tg-promo-agent, он не коммитится (см. `.gitignore`) и в облаке не
нужен — раннер работает по строке.

### 3. Проверить

Вкладка **Actions** → workflow **«Промо-агент (реклама каналов)»** → **Run workflow** —
запустить вручную и посмотреть логи + уведомление в Telegram.

## Память между запусками

`promo_memory.json` — какие чаты уже получили пост (кулдаун 45 дней) и какие оказались
непригодны (кулдаун 14 дней), плюс тема, обработанная сегодня (чтобы не постить дважды
за день). Workflow сам коммитит обновлённый файл обратно в репозиторий после каждого
запуска — раннер одноразовый, без этого память бы не сохранялась.

## Локальный проект-источник

Тексты, баннеры и правила поиска изначально из локального проекта `tg-channel-agent`
(там же — отдельный бот-пульт с ручными командами и историей старой функции подписок).
Этот репозиторий — самостоятельная копия под облачный запуск, они не связаны кодом
напрямую; при правке текста/тем меняйте оба места, если нужно единообразие.
