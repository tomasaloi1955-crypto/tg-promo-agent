# tg-promo-agent

Промо-агент в облаке (GitHub Actions) — не зависит от того, включён ли ваш компьютер.
Раз в день ищет один публичный Telegram-чат под тему дня и публикует туда рекламный
пост одного из ваших каналов. Темы крутятся по кругу:

| Тема дня | Канал | Ссылка |
|---|---|---|
| спорт | Мусульманка на спорте | t.me/ilikeislamandsport |
| образование | Тамра | t.me/tamra_school |
| ИИ / автоматизация | Halal AI \| Freya | t.me/Halalaifreya |
| семья / ислам | Тамра | t.me/tamra_school |
| арабский язык | My Arabic | t.me/myarabicl |
| английский язык | I Speak English | t.me/i_speak_en |

Тексты постов — `promo_posts.json`, баннеры — `banners/*.png` (`make_banners.py`
их генерирует, Pillow).

## Как это работает

1. GitHub Actions запускает `promo.py` раз в день по расписанию (`.github/workflows/promo.yml`,
   время — cron в UTC, поправьте в файле под свой часовой пояс) — либо вручную кнопкой
   **Run workflow** на вкладке **Actions** в GitHub.
2. Агент ищет чат по ключевым словам темы дня (Telegram, глобальный поиск), отсеивает
   каналы (туда обычный участник не пишет), малолюдные и уже использованные чаты.
3. Вступает в подходящий чат, читает описание/закреп, спрашивает Gemini, разрешён ли
   там самопиар.
4. **Публикует пост СРАЗУ — без подтверждения человеком — но только если Gemini дал
   чёткий вердикт «allowed»** (не «conditional»/«unclear»: без человека, который бы
   перепроверил, эти случаи слишком рискованны, поэтому агент их просто пропускает и
   ищет следующий чат).
5. Присылает вам в Telegram сообщение с итогом — что опубликовано и куда, или почему
   сегодня публикации не было.

**Важно:** в локальной версии (`tg-channel-agent` на компьютере) каждый пост ждал
вашего подтверждения кнопкой. Здесь это сознательно убрано — GitHub Actions запускает
процесс разово по расписанию и не может слушать нажатия кнопок в Telegram. Это ваш
выбор при переносе в облако: полная автоматизация ценой более высокого риска бана/
спам-репорта, если Gemini где-то ошибётся в оценке правил чата.

## Настройка (один раз)

### 1. Секреты репозитория (Settings → Secrets and variables → Actions)

| Секрет | Что это |
|---|---|
| `API_ID`, `API_HASH` | с https://my.telegram.org → API development tools (те же, что в tg-channel-agent) |
| `TELETHON_SESSION` | строка-сессия аккаунта — получить `get_session_string.py` (см. ниже) |
| `GEMINI_API_KEY` | https://aistudio.google.com/apikey |
| `BOT_TOKEN` | токен бота-уведомителя у @BotFather (можно тот же, что у бота-пульта tg-channel-agent) |
| `OWNER_ID` | ваш числовой Telegram id (@userinfobot) — куда слать уведомления |

### 2. Получить `TELETHON_SESSION`

На компьютере, где уже авторизован `tg-channel-agent` (файл `userbot.session` существует):

```powershell
cd C:\Users\lima2\Downloads\tg-promo-agent
copy ..\tg-channel-agent\userbot.session .
venv\Scripts\python get_session_string.py
```

Выведет длинную строку — это и есть `TELETHON_SESSION` (храните только в GitHub Secrets,
никуда больше — она равносильна паролю от аккаунта). Файл `userbot.session` после этого
можно удалить из папки tg-promo-agent, он не коммитится (см. `.gitignore`) и в облаке не
нужен — раннер работает по строке.

### 3. Проверить

Вкладка **Actions** → workflow **«Промо-агент (реклама каналов)»** → **Run workflow** —
запустить вручную и посмотреть логи + уведомление в Telegram.

## Память между запусками

`promo_memory.json` — какие чаты уже получили пост (кулдаун 45 дней) и какие оказались
непригодны (кулдаун 14 дней), плюс тема, обработанная сегодня (чтобы не постить дважды
за день). Workflow сам коммитит обновлённый файл обратно в репозиторий после каждого
запуска — раннер одноразовый, без этого память бы не сохранялась.
